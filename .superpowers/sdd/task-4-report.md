### Function Specifications

#### `length_drift(baseline_mean_words, current_mean_words, threshold)`
Returns dict with keys:
- `baseline_mean_words`: input baseline
- `current_mean_words`: input current
- `drift_pct`: `abs(current - baseline) / baseline` (0.0 if baseline=0)
- `alarm`: `True` if `drift_pct > threshold`

#### `probe_lengths(model, tokenizer, prompts, *, max_new_tokens, temperature, seed, device)`
Returns dict with keys:
- `mean_words`: mean word count across all generated fables
- `mean_new_tokens`: mean token count of generated tokens (excluding prompt)
- `n_prompts`: number of prompts processed

### Justification for Implementation Choice

The brief's specification had `len(tokenizer.encode(fable).ids)` to measure tokens. However:

1. **Problem:** Re-encoding decoded text produces different token counts due to:
   - Tokenizer edge cases (replacement characters in small vocabularies)
   - BPE boundary handling changes between decode→encode cycles
   - Result: Could be 2x larger than original token count

2. **Solution:** Measure actual generated tokens via `len(new_ids)` where `new_ids` are the tokens from model.generate()

3. **Validation:** This makes semantic sense:
   - "new_tokens" naturally means tokens generated by the model
   - Test assertion `assert a["mean_new_tokens"] <= 12` expects this
   - `max_new_tokens` is the model generation limit, not a re-encoding limit
